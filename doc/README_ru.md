# Rule34 Artist Finder 🎨🔍

Многопоточное десктопное приложение на Python (Tkinter) для умного поиска, анализа и массового скачивания артов с Booru-платформ.

> [!IMPORTANT]
> Большинство тулз для бору (imgbrd-grabber, DanbooruDownloader и т.п.) построены вокруг одного — скачать по тегу. Эта заточена под другую задачу: **найти, какие авторы чаще всего рисуют под конкретным тегом**, а дальше их можно закинуть в очередь и скачать всё разом. Она не пытается заменить большие мультисайтовые загрузчики (те покрывают куда больше сайтов) — это конкретно про поиск авторов.

## 🌟 Основные возможности

* **Умный поиск авторов**: Сканирует тысячи постов по вашим тегам и находит художников, которые чаще всего рисуют в этом жанре.
* **Поддержка нескольких API**: Работает с `Rule34.xxx`, `AllTheFallen.moe` и `Rule34.paheal.net`.
* **Продвинутые фильтры**:
  * Исключение ИИ-генераций (`ai_generated`).
  * Исключение контента с рейтингом `Questionable`.
  * Лимиты по количеству скачиваний и минимальному числу постов у автора.
* **Многопоточное скачивание (Очередь)**: Скачивание оригиналов изображений работает в несколько потоков в фоне (число потоков настраивается в разделе "Сеть и производительность" — см. ниже). Вы можете продолжать пользоваться программой и добавлять новых авторов в очередь на лету.
* **Система оценок и блэклисты**: Авторам можно ставить оценки (👍 Отлично / 👌 Нормально / 👎 Херово). "Херовых" авторов можно автоматически пропускать при скачивании или навсегда скрыть из поиска.
* **AI-Аналитика**: Встроенная поддержка локальных нейросетей (через Ollama) и облачных (Gemini / OpenAI) для анализа ваших запросов и предложения новых тегов.
* **Шифрованное хранение учётных данных**: API-ключи и User ID хранятся отдельно от остальных настроек и, если установлены необязательные пакеты `keyring` и `cryptography`, по-настоящему *шифруются* ключом, который хранится в системном защищённом хранилище ОС (Windows Credential Manager / macOS Keychain / Secret Service на Linux). Без этих пакетов используется резервный вариант — обычное кодирование base64 (это НЕ защита), о чём в лог пишется предупреждение. См. "Необязательные зависимости" ниже. В более ранних версиях это описывалось как "безопасное хранение", хотя на деле выполнялось лишь кодирование base64+zlib — это было неточно, и здесь это исправлено как в коде, так и в описании.
* **Автоматическая проверка обновлений**: При запуске приложение может (по желанию, переключатель в Настройках) проверить GitHub Releases в фоне и, если есть новая версия, предложить открыть страницу релиза. Само приложение никогда не скачивает и не заменяет свой исполняемый файл.
* **Более плавный зум**: Просмотрщик изображений теперь приближает "от курсора мыши" (а не только от центра), с мгновенным черновым превью на каждый щелчок колеса и отложенным качественным ресайзом, который считается в фоновом потоке — крупные картинки больше не "дёргаются" при зуме.

## 🛠 Установка и запуск (для разработчиков)

1. Убедитесь, что у вас установлен **Python 3.8+**.
2. Клонируйте проект и установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```
3. Запустите приложение:
   ```bash
   python main.py
   ```

### Необязательные зависимости (шифрованное хранение учётных данных)

В `requirements.txt` включены `keyring` и `cryptography` — они нужны для настоящего шифрования ваших API-ключей/User ID (см. "Шифрованное хранение учётных данных" выше). Если по какой-то причине вы не хотите их устанавливать, приложение всё равно будет работать — просто откатится на старое кодирование base64 для учётных данных и запишет в лог предупреждение, что это не является настоящей защитой.

## 📁 Где хранятся ваши данные

Настройки, учётные данные, история поиска и логи больше не пишутся рядом с исполняемым файлом / в текущую рабочую директорию (это могло незаметно не работать при установке в `Program Files`, либо разбрасывать данные в зависимости от способа запуска). Теперь они хранятся в стандартном каталоге данных пользователя:

* Windows: `%APPDATA%\Rule34ArtistFinder`
* macOS: `~/Library/Application Support/Rule34ArtistFinder`
* Linux: `$XDG_DATA_HOME/Rule34ArtistFinder` (обычно `~/.local/share/Rule34ArtistFinder`)

Если вы обновляетесь со старой версии, существующие `r34_settings.dat`/`found_artists.dat` и т.д., найденные рядом с приложением, автоматически переносятся туда при первом запуске — ничего не потеряется.

## 📦 Сборка автономного .exe (Windows)

Проект настроен для компиляции в единый исполняемый файл с помощью `PyInstaller`. Все ресурсы (иконки) будут вшиты внутрь приложения.

Выполните в корневой директории:
```bash
pyinstaller --noconsole --onefile --add-data "assets/1.png;assets" main.py
```
Готовый файл `main.exe` появится в папке `dist/`.

## 🍏 Запуск на macOS

### Из исходников

Если ваш Python установлен через **Homebrew**, Tkinter — отдельный пакет и по умолчанию не устанавливается (в официальном инсталляторе с python.org он уже включён):
```bash
brew install python-tk@3.11
```
После этого запускайте как обычно:
```bash
python3 main.py
```

### Запуск готового приложения (из Releases)

Сборка для macOS (`Rule34_Artist_Finder-macOS.zip` на странице Releases) не подписана Apple Developer ID, поэтому **Gatekeeper заблокирует первый запуск** сообщением вроде "Apple не удалось проверить это приложение на наличие вредоносного ПО" или "...от неизвестного разработчика". Это ожидаемо для неподписанного приложения и безопасно обходится:

1. Разархивируйте файл — получится `Rule34_Artist_Finder.app`.
2. **Правый клик** (или Control+клик) на приложении → **Открыть** → подтвердите **Открыть** в появившемся диалоге. (Обычный двойной клик просто повторит предупреждение без возможности продолжить.)
3. Если вместо этого macOS пишет, что приложение **"повреждено и не может быть открыто"** (более строгое сообщение Gatekeeper на новых версиях macOS), снимите флаг карантина через Терминал:
   ```bash
   xattr -cr /путь/до/Rule34_Artist_Finder.app
   ```
   и повторите шаг 2.
4. Это нужно сделать только один раз — после первого успешного запуска macOS запомнит ваш выбор.

## ⚙️ Управление ключами API
Для обхода серверных лимитов на запросы рекомендуется использовать ключи API.
Вкладка **"Подключение и Авторизация"** позволяет ввести ваш `User ID` и `API Key` для выбранного сайта. Настройки применяются на лету и надежно сохраняются при закрытии программы (о том, как они защищены на диске, см. "Шифрованное хранение учётных данных" выше).

## 🌐 Настройки сети и производительности

Раздел "Сеть и производительность" (под фильтрами скачивания) позволяет настроить:

* сколько потоков используется для скачивания файлов, проверки их размера и проверки тегов при поиске авторов (раньше было зашито в код: 8/32/4);
* необязательный HTTP(S)-прокси для всех запросов к Booru API (полезно за корпоративным прокси). Обратите внимание: сейчас это применяется только к запросам Booru API, но не к запросам к ИИ-провайдерам во вкладке "AI Аналитика".
